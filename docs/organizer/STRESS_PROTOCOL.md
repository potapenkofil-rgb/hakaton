# Протокол сценариев и стресс-тестирования

Цель протокола — сделать сравнение воспроизводимым. BASE, обязательный stress и дополнительные исследования не должны сливаться в один набор изменённых чисел.

## BASE

`BASE` использует базовый спрос и исходные цены/параметры. Своевременно заказанные доступные плановые объёмы поступают по плану. Reliability не используется как автоматический delivery multiplier.

## MANDATORY_STRESS

Обязательный stress одинаков для всех команд.

| Параметр | 2035–2037 | 2038 | 2039 | 2040 |
|---|---:|---:|---:|---:|
| базовый общий спрос | 100% | 115% | 115% | 115% |
| базовый критический спрос | 100% | 115% | 115% | 115% |
| Earth-Core variable price | 100% | 125% | 125% | 100% |
| Earth-Flex variable price | 100% | 125% | 125% | 100% |
| Lunar-ISRU actual delivery | plan | 55% plan | 75% plan | plan |
| ceiling `losses/throughput` | n/a | <=2% | <=2% | <=2% |

Резервные тарифы, CAPEX и прочие цены обязательным +25% shock не меняются.

> **Важно:** 55% и 75% — уже фактические доли поставки Lunar-ISRU в обязательном stress. Не умножайте их ещё раз на reliability.

Mandatory stress не накладывается автоматически на high-demand и геополитический сценарий.

## Анализ чувствительности

Sensitivity analysis меняет один или несколько параметров в обоснованном диапазоне и показывает:

- влияние на cost/service/inventory;
- границу нарушения;
- насколько вывод устойчив к изменению параметра.

Low/high demand из organiser data — готовые контрольные точки чувствительности, но команда может добавлять свои диапазоны как `TEAM_ASSUMPTION`.

## Сценарии рисков команды

`TEAM_*` сценарий должен сохранять:

- список изменённых факторов;
- исходные и новые значения;
- период;
- основание диапазона/вероятности;
- правило комбинации шоков;
- результат и violation list.

Если статистики нет, сценарный или интервальный подход честнее, чем вымышленная точная вероятность.

## Reverse stress

Reverse stress ищет условие, при котором план перестаёт выполнять заданное ограничение. Например, это может быть threshold по цене, задержке, объёму недопоставки или спросу. Метод опционален, если не входит в обязательную часть конкретной реализации.

## Robust analysis

Robust analysis задаёт явное uncertainty set и показывает цену защиты от него. Применение robust optimization не обязательно; если используется, uncertainty set должен быть объяснимым.

## Monte Carlo

Monte Carlo допустим только при раскрытии:

- распределений и их происхождения;
- зависимостей;
- количества испытаний;
- random seed;
- точности/доверительных интервалов, если они заявлены.

Десять придуманных сценариев не означают «10% реальной вероятности».

## Изоляция и воспроизводимость

Каждый запуск должен сохранять:

```text
scenario_id
plan_id
input version
team assumptions
random seed (если применимо)
result timestamp/version
```

Сравнение BASE/STRESS проводится на одном plan definition либо с явно показанной адаптацией решения. Нельзя скрытно менять и environment, и strategy, а затем приписывать весь эффект только stress.
