# Validation vectors

Каталог `validation/` содержит маленькие синтетические тест-векторы для проверки арифметики и смысла расчётного ядра.

## Что они проверяют

- материальный баланс;
- separation shortage/inventory;
- take-or-pay;
- резервный платёж;
- потери от throughput;
- 45-дневный резерв;
- ограничение мощности;
- вложенность критического спроса;
- запрет повторного умножения уже заданной stress-delivery на reliability.

## Чего они не проверяют

Успешное прохождение этих тестов не означает, что команда выбрала хорошую стратегию снабжения, инвестиции или контрактную архитектуру. Здесь нет «правильного» source mix и нет теста, который требует Lunar-ISRU, Earth-New или любую конкретную закупку.

## Как использовать

Команда должна воспроизвести ожидаемые результаты из `expected_checks.json` в своём стеке. Дополнительно нужны собственные boundary tests и интеграционная проверка полного `MANDATORY_STRESS` на реальных входах кейса.

Если реализация использует другой внутренний временной шаг или типы данных, численный результат контрольного примера всё равно должен совпадать в пределах заранее раскрытой точности.
