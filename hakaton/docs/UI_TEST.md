# Проверка интерфейса за 5 минут

## Запуск

Из корня репозитория:

```
set PYTHONPATH=src
python -m fuelhub serve
```

Откроется http://127.0.0.1:8765/ (порт можно сменить: `--port 9000`).
Остановить — Ctrl+C. Никаких установок не нужно, только Python 3.10+.

## Тестовые планы (`results/plans/`)

| План | Что это | BASE | MANDATORY_STRESS |
|---|---|---|---|
| `base-v1` | основной: Core + Flex, Earth-New с 2038, ISRU с 2038, ZBO в 2037, CAPEX 1790 | исполним, нарушений нет | НЕ исполним: дефицит 30 т в 2039 и 53 т в 2040, резерв 45 дней сорван |
| `stress-response` | тот же, но с 2038 добавлены заказы у Flex и бронь Emergency — то, что оператор может изменить после того, как увидел стресс | переполнение бака в 2039–2040 (заказано больше, чем нужно в спокойном году) | исполним, дефицита нет |
| `earth-only` | без Луны: Core + Flex + Earth-New, ZBO; CAPEX 540 | исполним, PV 9 467 — дешевле base-v1 | резерв сорван в 2039–2040, дефицит 31 т |
| `no-investments` | ничего не строим | дефицит 90 т в 2040, сервис 77 % | всё плохо: потери 4,5 % > 2 %, дефицит 234 т |
| `broken` | специально кривой | 11 нарушений: заказ 200 у Core при мощности 190, заказ больше брони, ISRU без финансирования, ZBO в 2035, бак 300 т при ёмкости 70 | ещё хуже |
| `invalid` | ошибки ввода | расчёта нет: отрицательный заказ, канал F, год 2041 | — |

## Что покликать

1. **Открыть страницу.** Сразу загружен `base-v1` в BASE, зелёная полоса «исполним, нарушений нет». Внизу — баланс по годам, деньги, поставки по каналам.
2. **Сценарий → MANDATORY_STRESS.** Полоса становится красной: 2 жёстких нарушения (RESERVE_45D 2039, 2040) и 2 справочных (сервис 91,8 % и 88,1 % — требования BASE, в стрессе только показываются). В балансе строки 2039–2040 подсвечены, дефицит 30,3 и 53,3 т. В поставках ISRU 2038: план 40, факт 22 (55 %).
3. **«Сравнить BASE / STRESS».** Внизу таблица: итоговые расходы 12 253 против 12 623, дефицит 0 против 83,6 т, PV, стоимость тонны.
4. **Поменять число.** В таблице плана у Earth-Core 2035 поставить заказ 200 (вместо 95). Через полсекунды пересчёт: нарушение `CAPACITY_EXCEEDED 2035 A: факт 200 > 190, превышение 10`. Вернуть 95 — нарушение исчезает.
5. **Снять галочку ZBO.** Появится в стрессе `STRESS_LOSS_LIMIT 2038–2040: 0,045 > 0,02`, в BASE — переполнение бака. Вернуть.
6. **Открыть → `invalid` → Открыть.** Красное поле: «План не принят: … отрицательный объём: -5 … неизвестный канал F … год 2041 вне горизонта». Расчёта нет, старые таблицы остаются.
7. **Открыть → `broken`.** 11 нарушений с годом, фактом, порогом, превышением и причиной словами.
8. **Открыть → `base-v1`, изменить имя плана на `my-test`, «Сохранить».** Полоса «Сохранено: results/plans/my-test.json», план появился в списке. Обновить страницу (F5), выбрать `my-test`, «Открыть» — все числа те же.
9. **CSV / XLSX.** Скачивается `my-test_BASE.csv` (длинный формат: год, сущность, показатель, значение, единица) или `.xlsx` с листами по таблицам. Числа совпадают с экраном.
10. **Открыть → `stress-response`, сценарий MANDATORY_STRESS.** Исполним, дефицита нет: это ответ на пункт 2. Переключить на BASE — переполнение бака: план для стресса в спокойном году избыточен, реакция должна зависеть от сценария.

## Если что-то не так

- Страница пустая или «ошибка» вверху — посмотреть консоль браузера (F12) и вывод сервера в терминале.
- «Address already in use» — порт занят, запустить с `--port 9000`.
- Числа на экране не совпадают с `python -m fuelhub calc results/plans/base-v1.json` — это баг, писать Филиппу.
