# Сценарии

Сценарии организатора хранятся отдельно от решений команды. Их задача — изменить среду расчёта, а не подсказать стратегию снабжения.

## Пространства имён

| Префикс / ID | Смысл | Кто задаёт |
|---|---|---|
| `BASE` | контрольный стандартный сценарий | организатор |
| `MANDATORY_STRESS` | обязательный стресс | организатор |
| `TEAM_*` | дополнительные исследования, sensitivity, reverse stress, геополитические и иные сценарии | команда |

Файлы `base.yaml` и `mandatory_stress.yaml` относятся к `CASE_INPUT`. Команда не должна молча перезаписывать их своими гипотезами. Собственные сценарии следует хранить отдельно и маркировать как `TEAM_ASSUMPTION`.

## BASE

`BASE` не изменяет спрос, цены или поставки. Коэффициенты reliability из `data/supply_sources.csv` в BASE **не** являются автоматическими множителями объёма поставки.

## MANDATORY_STRESS

Обязательный stress начинается в 2038 году:

- общий и критический базовый спрос: ×1.15 в 2038–2040;
- переменная цена Earth-Core: ×1.25 в 2038–2039, затем ×1.00 в 2040;
- переменная цена Earth-Flex: ×1.25 в 2038–2039, затем ×1.00 в 2040;
- Lunar-ISRU фактически поставляет 55% плана в 2038, 75% в 2039 и плановый объём в 2040;
- с 2038 действует ограничение `losses / throughput <= 0.02`.

Резервные тарифы, CAPEX и прочие цены этим обязательным ценовым шоком не меняются.

### Не удваивайте отказ ISRU

`0.55` и `0.75` в `actual_delivery_share` — уже фактические доли поставки для обязательного стресса. Нельзя автоматически умножать их ещё раз на `reliability_profile`.

## Изоляция сценариев

Обязательный stress не смешивается автоматически с `high_total_t`, собственным риском или бонусным геополитическим сценарием. Если команда хочет исследовать комбинацию шоков, это отдельный `TEAM_*` сценарий с явными правилами.

## Сценарии команды в этой папке

| ID | Что меняет | Правила |
|---|---|---|
| `TEAM_LOW_DEMAND` | спрос по колонке `low_total_t` | как в BASE |
| `TEAM_HIGH_DEMAND` | спрос по колонке `high_total_t` | как в BASE |
| `TEAM_GEO_PRICE` | цены Core и Flex +50 %, Earth-New и Emergency +30 % в 2038–2040 | как в BASE |
| `TEAM_EARTH_NEW_DELAY` | Earth-New не поставляет в 2038 | как в BASE |
| `TEAM_CORE_SHORT` | Earth-Core привозит 90 % в 2039 | как в BASE |
| `TEAM_FLEX_SQUEEZE` | весь обязательный стресс плюс Earth-Flex 80 % в 2039–2040 | как в MANDATORY_STRESS |

Поле `constraint_profile` в YAML говорит, чьи ограничения из `data/constraints.csv`
применяются как жёсткие: у производных от базового сценария это `BASE` (сервис
97 % и 99 % обязателен), у комбинированного стресса `MANDATORY_STRESS`. Без поля
жёсткими считаются только правила `ALL` и правила с точным именем сценария.
Основания диапазонов записаны в `notes` каждого файла и в `docs/RISKS.md`.
